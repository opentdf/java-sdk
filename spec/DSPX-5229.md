# Assertion bindings embed the whole aggregate hash: ~745 MB per assertion at 50 TiB (spec + all SDKs)

## Summary
Found in the DSPX-5124 large-TDF runtime analysis (virtru-corp/adr docs/decisions/dspx-5124-analysis/, runtime-limits-{go,java,web}.md).
ProblemEvery SDK builds an assertion's binding by signing (JWS) a payload that contains base64(aggregateHash ‖ assertionHash). The aggregate hash is the concatenation of every segment hash, so it grows linearly with payload size. Each assertion therefore adds a full copy of it to the manifest:
SDK
Extra manifest bytes per segment, per assertion
Where
Go
+28.45 B (57 B in legacy hex mode)
assertion binding in sdk/ (see runtime-limits-go.md)
Java
+28.45 B (about double in hex/HS256 mode)
see runtime-limits-java.md, finding F2
Web
about +28 B (GMAC goes from 36 to 64.4 B/segment)
lib/tdf3/src/assertions.ts:256,268
At 50 TiB with 2 MiB segments (26.2M segments) that is about 745 MB of JWS per assertion. Consequences:
Java: one assertion lowers the manifest String ceiling from 41.4 TiB to 32.1 TiB at 2 MiB segments. The cmdline always adds the system-metadata assertion, so the Java cmdline tops out at 32.1 TiB.
Go: three assertions at 2 MiB segments push the manifest past 4 GiB, which triggers the ZIP local-header truncation bug (see the related Go ZIP64 ticket).
Web: it eats into the V8 string limit (2^29−24 chars).
Manifest streaming (DSPX-4584, DSPX-4905) does not remove this cost; it is in the format.
Proposed directionBind assertions to a fixed-size digest of the aggregate hash, e.g. SHA-256(aggregateHash), or to the root signature, instead of the raw concatenation. That is a spec change (BaseTDF assertion binding) and needs:
backward-compatible verification of existing TDFs that use the current binding;
a version or flag so readers know which binding form is in use;
cross-SDK interop tests in xtest.
Acceptance criteriaSpec updated with the new binding form and a compatibility rule.
Go, Java and Web write the new form, and read both forms.
The manifest size per assertion is constant, independent of payload size.
xtest interop coverage for both binding forms.
